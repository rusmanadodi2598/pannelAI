# Strict Antislop Rules: Comment and Text Hygiene

## 1. Role Definition

You are acting as a **Staff Engineer reviewing prose that a machine wrote**. Most of this repository is authored or
edited by AI coding agents, and comments are the surface where generated text shows first: correct in fact, wrong in
shape. The objective is that every comment carries information the code does not already show, and that nothing in the
tree reads as generated by habit rather than by need.

This protocol is **MANDATORY** for comments in every hand-authored file under `app-*/**`, `scrypts/**`, `docs/**` and
the root documentation. Generated output (`*_gen.go`, `*.pb.go`, `openapi.json`, anything under `node_modules`) is out
of scope, for the same reason AGENTS.md §1.1 exempts it: it is not hand-authored, and splitting it is not meaningful.

The filter rejects *technique without purpose*, not technique. A long comment that carries five distinct constraints is
craft; a short one that restates the line under it is noise.

---

## 2. Hard Rules, Machine-Enforced

Every rule here is checked by `scrypts/gates/antislop.sh`, wired into `scrypts/gates/all.sh`, CI
(`.github/workflows/gates.yml`) and the `pre-commit` hook. A rule with no check behind it is listed in §3 instead, so
the document never claims enforcement it does not have.

### 2.1 No Em Dash or En Dash (R-02)

- The characters `—` and `–` are forbidden outright in text. Use a comma, a period, a colon, a semicolon or parentheses. <!-- antislop:ignore: naming the forbidden characters is the rule, not a violation -->
- Choose by the mark's actual job: an explanation or consequence takes a colon or a new sentence, an appositive takes a
  comma, a mid-sentence aside takes parentheses. **Never substitute the character and leave the spacing behind**, which
  is how `colliding , so` reached six files in one automated sweep.
- Enforced on changed files, the same incremental contract AGENTS.md §1.1 and §1.2 use. `docs/**` and `AGENTS.md` are
  excluded by name because they carry legacy debt this repo has not decided to sweep; the exclusion is printed on every
  run that touches them, so it stays a visible decision instead of a quiet hole.

### 2.2 No Decorative Separators or ALL CAPS Banners

- A section name padded with repeated characters (`# ----- runner choice -----`, `// ========== ROUTES ==========`) is
  the pattern. Keep the label as one plain line, or drop it if it names a category nobody needs named.
- Markdown table rules (`| --- |`) are structure, not decoration, and are never flagged.

### 2.3 No Signature Echo

- A comment that repeats what the next line already shows adds reading load and no information.
  `// strPtr returns a pointer to a copy of value` above `func strPtr(value string) *string { return &value }` is the
  shape. Delete it.
- The exception is a fact the signature cannot carry: `// strPtr exists because a table row cannot take the address of a
  string literal inline` stays, because Go gives no other way to write it.

### 2.4 No Workflow Narration, End Markers, or Decorative Emoji

- `// Step 1: validate`, `// First... then... finally` narrate control flow the code already shows. If the flow is hard
  to follow, that is a structure problem, not a missing-comment problem.
- A closing brace already ends its block; `} // end if` is habit.
- Emoji used as decoration (`✅`, `🚀`, `🔒`) is visual noise and the default AI vocabulary. Write the fact in words.

### 2.5 Suppression Comments State a Constraint (AGENTS.md §1.4)

- Every `//nolint:<name>` carries `// reason: <why>` naming the constraint it protects. A bare directive with no reason
  fails the gate.
- The clause used to demand a ticket ID as well. This repository has no ticket tracker, so the ID half was
  unsatisfiable and the whole rule went unenforced; §1.4 was amended on 2026-10-05 to keep the part a machine can
  check and the part that carries information.

### 2.6 A Comment's Length Is Its Fact Count

- One line per irreducible fact. Past about eight lines the block is being argued rather than stated.
- The gate fails a Go doc block over 16 lines and warns past 10, on changed files. A block that genuinely holds five
  constraints takes five lines; that is a pass, not a near-miss, and the fix is never to compress a fact into fewer
  words.

## 3. Review Rules, Not Yet Machine-Checked

These need a reader. They are listed here so they are enforceable in review, and marked honestly as unautomated so no
one mistakes the document for a gate report.

- A comment earns its place by adding information the code does not show. Being true is not sufficient.
- One concise comment per logical block, not one per line.
- Sentence case, natural developer voice. "This function is responsible for validating whether the supplied credentials
  are valid" is stiff; "Validate credentials before issuing a token" is the same fact said normally.
- A TODO names an actionable task. "Future improvements" is a feeling.

**Not a ban.** Never remove a comment that explains business logic and intent, an architectural decision, a security
consideration, a performance trade-off, concurrency behaviour, a protocol detail, an API contract, a workaround, an
edge case or assumption, or a licence notice. Value is not length, and the most common way this filter is misapplied
is deleting exactly these.

---

## 4. Citations: What May Be Referenced, and From Where

- A `draft NNN` or audit-pass reference in a comment below a Go file's `package` line is scratch work pointing at a
  document that closes and moves. State the fact; drop the pointer. The gate warns rather than fails, because the tree
  carries 142 of them and a commit must not be held hostage to lines its author did not write.
- The same reference inside the `@reason` field of the AGENTS.md §1.2 file header is **by design**. §1.2 names that
  field as where a file's rationale lives, and 701 citations sit there legitimately. The gate ignores that region for
  this rule.
- `SPEC-API-001 §n` and `AGENTS.md §n` pointers stay. Those name the live contract and the live rule, which is a
  reference, not a stale ticket.

---

## 5. Exempting a Line

A line that quotes a violation rather than committing one may carry a trailing `antislop:ignore` marker. Every
exemption is printed when the gate runs, so an exemption stays a decision a reviewer sees. `openapi.json` is exempt as
generated output; the gate itself is exempt because its pattern constants contain the forbidden characters as data.

## 7. Where the Wider Rule Set Lives

This file states the rules **this repository enforces**. The upstream antislop skill that R-02 and its siblings come
from is a CLI-level resource installed per machine, covering interface and copy rules as well, and it is deliberately
not vendored here: a repo-committed copy would drift from a tool a developer upgrades independently. Route to it from
your own agent configuration, and treat this document as the contract for anything a gate can check.
